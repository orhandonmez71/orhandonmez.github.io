MUCUR GRMHD 2D Meridional Plane

An axisymmetric general-relativistic magnetohydrodynamics code for accretion flows and jets around rotating (Kerr) black holes. It evolves the full meridional plane (r, θ), from pole to pole, with all three components of velocity and magnetic field.

  • Release v4l
  • Fortran 90 · MPI · PARAMESH
  • Kerr space-time, Boyer–Lindquist and Kerr–Schild
  • 70 modified-gravity and alternative space-times
  • Validated against the Blandford–Znajek power

What the code does

The code solves the equations of ideal GRMHD for a perfect fluid with an ideal-gas equation of state on a fixed, stationary, axisymmetric black-hole background. All quantities depend on (t, r, θ), with 0 ≤ θ ≤ π. Every velocity, momentum and magnetic-field component is evolved, so the gas can rotate and poloidal field can be wound into a toroidal component. Frame dragging creates toroidal field from poloidal field in exactly this way, so the Blandford–Znajek process works self-consistently in the code.

Integrated rates are totals through a sphere, so the results compare directly with 3D simulations and with analytic accretion formulae.

Typical applications

  • Bondi–Hoyle–Lyttleton accretion of a wind moving along the spin axis onto a Kerr black hole, with or without magnetic field
  • Spherical (Bondi, Michel) accretion, with or without a radial field
  • Feeding a spinning hole through an equatorial window with both poles open
  • Magnetised black holes (split monopole), extraction of rotational energy by the Blandford–Znajek process, and jet formation
  • Any axisymmetric initial state: tori, shells, clouds, custom magnetic fields

Beyond Kerr: 70 modified-gravity and alternative space-times

The code is not limited to the Kerr metric. Besides Kerr, it evolves the flow in 70 further black-hole space-times from modified theories of gravity, quantum-corrected and regular black holes, nonlinear electrodynamics, and black holes surrounded by dark matter. With the same code, the same set-up and the same diagnostics, you can see directly how the theory of gravity changes accretion, outflows and jets.

How the metrics are implemented

  • Every space-time has the full θ dependence of the metric, so the whole (r, θ) plane is evolved consistently, not just the equator.
  • The metric derivatives come from the complex-step method, which is exact to round-off.
  • Each metric was checked against the formulas in the literature, its derivatives against finite differences, its north–south symmetry, and its Kerr or Schwarzschild limit.

Good to know

  • The alternative space-times use Boyer–Lindquist-type coordinates, so the grid lies outside the horizon. The code checks this at start-up.
  • The parameters of each theory (couplings, charges, hair, dark-matter density and so on) are set in the user header file.
  • A new space-time can be added from a template and is checked the same way. If the metric you need is not in the list, we can add it.

The computational domain

The grid covers rmin ≤ r ≤ rmax and 0 ≤ θ ≤ π, the full meridional half-plane. Both poles are boundaries of the grid, so outflows along the spin axis in both directions are part of the solution.

In Boyer–Lindquist coordinates the inner boundary lies outside the horizon. In Kerr–Schild coordinates it lies inside the horizon, between the inner and outer horizons, so the ergosphere and the horizon are both on the grid. This is the natural choice for jet launching.

Gas enters through the outer boundary: on the upstream hemisphere for a wind along the axis, at all angles for spherical inflow, or through a window around the equator.

Validated: the Blandford–Znajek power is reproduced to within a few per cent

The standard test for jet physics around a spinning black hole is a split-monopole magnetic field on the hole, in a strongly magnetised plasma (σ = b²/ρ = 50). Frame dragging forces the field lines to rotate, and they carry an outgoing Poynting flux that must match the Blandford–Znajek formula:

PBZ = κ Φ² ΩH²,   κ = (1 + 1.38 ΩH² − 9.2 ΩH⁴) / 6π,   ΩH = a / 2r+

We ran the test for three spins in Kerr–Schild coordinates on 1024 × 256 cells, with the horizon and the ergosphere on the grid.

Checks of the scheme

  • Before compilation, every new formula was checked against a line-by-line Python transcription of the scheme. The metric derivatives match finite differences to 2 × 10−10, and the 3+1 split and geometric sources are exact to round-off.
  • Equatorial symmetry, the polar-axis boundary conditions and the corner ∇·B on the axis are preserved to round-off.

What a run produces

  • Accretion rates of mass, energy and angular momentum (Ṁ, Ė, L̇) through spheres at four radii, as functions of time
  • Binary VTK snapshots with 50 quantities on the (R, z) half-plane, ready for VisIt and ParaView: densities, velocities, four-velocities, Lorentz factor, Mach numbers, Bernoulli parameter, fluxes, magnetic field, magnetisation, plasma β, the magnetic flux function ψ and more
  • A time series of the magnetic flux on the hole and the MAD parameter φBH
  • Floor statistics, so the effect of numerical floors can be checked
  • Python tools for maps, radial profiles, time series and the Blandford–Znajek analysis

Physics extracted from the output

  • Accretion rate, efficiency and angular-momentum transport
  • Shock structure, sonic surfaces, bound and unbound gas
  • Magnetic flux on the horizon and the magnetically arrested state
  • Blandford–Znajek power and identification of the jet

All quantities are in geometrised units, G = c = M = 1, with lengths and times in M. The manual gives the conversion to physical units.

Working with the code: collaboration

The source code is not publicly distributed. The tests above show that the code works reliably in the (r, θ) plane around Kerr black holes. If you have an astrophysical problem that fits this framework, we are happy to solve it together as a collaboration.

  1. You

    Describe the problem

    The physical system, spin, initial state, magnetic field, how gas is fed, and the quantities you want to measure.
  2. We

    Check feasibility

    We check that the problem is axisymmetric and fits the meridional-plane code, and agree on a plan.
  3. We

    Prepare the set-up

    We write the user header file and the initial and boundary data for your problem.
  4. You

    Run the simulations

    You run the code with the prepared set-up, following the user manual.
  5. Together

    Analyse and publish

    We interpret the results together, and they go into a joint publication.
